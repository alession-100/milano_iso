## Changes
1. **Language switch** (ADR-0006).
   - Add an IT/EN control in the toolbar.
   - `?lang=it|en` sets the initial language; the choice is remembered in `localStorage` (try/catch); the default is Italian.
   - Switching updates every UI string live, including the tile notice, the info card, search, layers, the minimap label, the rotation and day/night controls, every aria-label, and `<html lang>`.
   - Feature names are never translated.
   - Add a unit test that every i18n key has both languages, and that no UI string bypasses i18n (for example a grep-based test over `web/src` for literal user-facing strings in DOM code; document the allow-list).
2. **Focus and contrast.**
   - A visible focus indicator on every control, in both modes, with contrast >= 3:1 against its surroundings. Fix the night-mode toggle focus ring (G4 carry-over 2).
   - The rotation buttons get a proper night look (T-5.3b note).
   - Measure text contrast (>= 4.5:1) and component boundaries (>= 3:1) with a script that samples the real rendered background behind each control in both modes (as the G4 reviewer did), and report the worst cases.
3. **Keyboard.**
   - Every control can be reached with Tab in a logical order: toolbar, map, the controls at the right, the info card when open, attribution.
   - The map container is focusable and has a label. Its key bindings (arrows, +/−, Q/E, Escape) are listed in a short help that can be opened from the toolbar (i18n). There is no keyboard trap.
   - Focus moves into the info card when it opens and back when it closes (verify it is so).
4. **Touch.**
   - Every target is at least 44x44 CSS px.
   - Under touch emulation at 412x915, check that pan, pinch, tap-to-pick, the rotation buttons, search, layers and the minimap button all work.
5. **Layout.**
   - At 1280x720 and 412x915, in both modes, with the info card open, search results open and the tile notice shown:
     - no control overlaps another, the attribution, the notice or the card;
     - no horizontal page scroll.
   - Test with bounding boxes in e2e.
   - The `?debug` overlay must not cover the notice (G3 carry-over 5).
6. **Reduced motion.** Rotation, fly-to after search, and inertia are all instant with `prefers-reduced-motion` (e2e for each).
7. **Screen reader semantics.**
   - Every control has an accessible name.
   - The info card is announced (dialog or live region).
   - Search is a combobox with listbox semantics; "no results" and the tile notice are announced (live regions).
   - Check with Playwright's accessibility snapshot, and attach it to the report.
8. **Tile retry edge cases** (G3 carry-over 6): a retry must not hold a loader slot during the 2 s wait, and a tile no longer wanted is not retried. Add unit tests for both.
9. **E2E robustness.**
   - Move the "settle" helpers that each spec reinvented (tiles settled, frame rendered, draw calls stable) into `e2e/support.ts`, and use them in every spec that samples render state.
   - Add a short note in `e2e/support.ts` that wall-clock thresholds do not belong in e2e (T-5.1 review).
10. **Visual baselines.** If the visible toggle's style changes, regenerate the affected win32 baselines (delete them first) and list every changed baseline in the report. The approved map look itself must not change. Leave the `*-linux.png` files to the orchestrator.
