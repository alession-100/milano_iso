## Specification
- **Manifest:** on start, fetch `tiles.json` from `tiles/pilot/` relative to the page, or from `?tiles=` (ADR-0025). Check that `format_version`, `quantization.unit_m == 0.02` and the axis convention are as expected; otherwise show an error in the UI and stop.
- **Culling:** for each frame where the camera changed, compute the set of tiles whose `content_bbox_local` (3D) intersects the camera frustum, plus a margin of one tile ring for prefetch. Use pure, unit-tested functions.
- **Loading:**
  - Load at most 4 tiles at a time, nearest to the view centre first.
  - Use `GLTFLoader` (`KHR_mesh_quantization` is natively supported).
  - Keep `_FEATURE_ID` attributes for Phase 5 picking.
  - Cache up to N loaded tiles; N is a constant, start at 64, and evict least recently visible first, disposing geometries.
  - A failed tile shows in the test state and the console as a single error, without breaking the app.
- **Materials:** use `materialFor(layer)` with mesh names as layer names; strip the `#n` chunk suffix. Share one material instance per layer.
- **Attribution:** render the manifest's `attribution` entries in the corner element as links where a URL is known, with an i18n label "Dati" or "Data". The placeholder string goes away. It is visible on desktop and mobile without scrolling.
- **Draw calls:** read `renderer.info.render.calls` after a frame, and expose `{calls, triangles}` via `registerTestState('render', ...)` and `{loaded, loading, failed, visible}` via `registerTestState('tiles', ...)`.
- **Camera interplay:** T-3.1 adds controls in parallel. Use only `camera.ts` exports and the camera object. For bounds, export a function `contentBounds(manifest)` that returns {minX, maxX, minZ, maxZ} for T-3.1's `setBounds`; the orchestrator wires them together at merge.
- **e2e (`tiles.spec.ts`, using the fixture via `page.route('**/tiles/**', ...)`):**
  - the tiles load: `loaded` equals the expected visible count from the fixture manifest;
  - `failed` is 0;
  - the attribution text contains "OpenStreetMap contributors" and "Comune di Milano";
  - the draw calls are <= 300;
  - zero console errors (ADR-0012 filter only);
  - a screenshot is saved.
- **Real-data measurement** (local only, reported, not part of CI): `make web-tiles`, `npm run build`, and preview. Then measure, with the test hook, the tiles loaded and the draw calls at the default view and at the widest zoom (the 4000 m width; you may set the camera directly through the test hook or a query param if T-3.1's controls are not there yet). Save screenshots of the real pilot to `reports/artifacts/T-3.2/`.

## Acceptance criteria
1. The web typecheck, lint and unit tests pass, with culling and manifest tests included.
2. `npm --prefix web run build && npm --prefix web run e2e` pass using the fixture (no real data needed).
3. The fixture regenerates byte-identically (pytest), and `make test` exits 0.
4. The real-data report: the tiles loaded and the draw calls at the default view and at the widest zoom, plus 2 screenshots. Draw calls above 300 are a finding: report it, do not hide it.
5. `git status --short` empty; committed on `t-3.2`.
