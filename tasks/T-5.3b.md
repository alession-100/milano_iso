## Changes
1. **Toolbar.**
   - Top-left. It holds the search box and a "Livelli" / "Layers" button that opens the toggles.
   - Move the T-5.2 rotation buttons and the day/night toggle into it only if that improves the layout at 412 px. Otherwise leave them where they are. Either way, nothing may overlap: not the attribution, the tile notice, or the info card zone (right side panel on desktop, bottom sheet at 412 px, owned by T-5.1).
   - Controls are at least 44x44 CSS px, reachable with Tab, and every string goes through i18n (IT default, EN).
2. **Search.**
   - Fetch `index.json` lazily, on first focus of the search box, through `indexUrl(manifest)`.
   - Match on accent- and case-folded names: prefix matches first, then substring matches. Show at most 8 results, each with its kind label.
   - Group entries that share a name and kind into one result that lists the count (for example "Ca' Granda (2)"). Choosing it flies to the union bbox.
   - The results list is an ARIA combobox with a listbox. Arrow keys move, Enter chooses, Escape closes.
   - Choosing a result flies the camera to the entry: centre on `centre`, zoom to fit `bbox` within the zoom limits. With reduced motion, the move is instant.
   - Then call `select({ ref, source: 'search' })` with a `FeatureRef` built from the entry `ref`:
     - landmark -> `{layer:'landmark', landmarkId}`;
     - building -> `{layer:'buildings', key}`;
     - street -> `{layer:'roads', streetName, osmType, osmId}` (the first id);
     - green or water -> the matching layer with its osm id.
   - "No results" is announced.
3. **Layer toggles.**
   - Buildings, trees, markings, roads (with road areas and rail), water and green (with land use), and landmark details.
   - Toggles hide the matching meshes, including tiles loaded later. They render once, on demand.
   - They are remembered in `localStorage` (every access in try/catch) and settable with `?layers=...` for tests.
   - Hidden layers must not be pickable. Expose the visibility through the test hook, so T-5.1's picking can check it, for example a `layerVisible(name)` function in a small module.
4. **Minimap.**
   - Fetch `minimap.svg` through `minimapUrl(manifest)` and inline it in the DOM, parsed with `DOMParser`.
   - It is our own static file, but strip any `<script>` and `on*` attributes anyway.
   - Theme it with the existing CSS classes for day and night (T-4.3 mode).
   - Draw the current view footprint as a polygon (the camera's ground footprint, which rotates with T-5.2).
   - Click or tap on the minimap pans there.
   - Desktop: bottom-left, about 160 px. At 412 px it is collapsed behind a button.
   - Keyboard: the minimap is not a keyboard trap. A label says it is an overview; search is the keyboard route.
5. **Test hook.** `registerTestState('toolbar', ...)`: search query, result count, layer visibility, and the minimap view polygon.
6. **Tests.**
   - Unit tests:
     - accent and case folding (for example "duomo" finds "Duomo di Milano", "ca granda" finds "Ca' Granda");
     - ranking;
     - grouping;
     - mapping from index entry to `FeatureRef`;
     - minimap footprint math in all 4 azimuths;
     - the SVG sanitiser.
   - e2e (fixture):
     - typing finds a fixture building, the street and the landmark;
     - keyboard-only search flies there and calls select (check the selection state);
     - each toggle hides its layer (draw calls and test state) and survives a reload;
     - a minimap click pans;
     - 412 px layout has no overlaps (check bounding boxes of toolbar, attribution, notice and minimap);
     - zero console errors.
   - Visual: keep existing baselines valid by adding the toolbar and minimap selectors to `e2e/visual-hide-controls.css`. Add one new baseline: the toolbar with the search results open and the minimap, at both sizes (win32 only).
