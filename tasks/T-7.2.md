# T-7.2 - Attribution, licence compliance, About page and README with rebuild steps

- **Phase / depends on:** Phase 7. Independent of the host (T-7.0); the deploy URL is added in T-7.3.
- **Owner:** executor
- **Branch:** t-7.2

## Goal
- Anyone can see where the data comes from and under which licence.
- Anyone can rebuild the site from a clean clone by following the README.

## Changes
1. **Licence obligations.** For each source in `docs/DATA_SOURCES.md`, state in a table what its licence requires of us, with the licence URL:
   - the attribution text;
   - share-alike, for example ODbL on the tiles as a derived database;
   - the licence notice to ship;
   - whether the derived tiles must be offered under the same licence.

   Write NOT FOUND where the text does not say, and do not interpret beyond it. If share-alike applies to the tiles, say what we must publish, and where.
2. **About page or panel** in the web UI, reachable from the attribution line and by keyboard:
   - what the map is;
   - the sources with their licences and links;
   - the date of the data;
   - the build version (git hash or date);
   - a link to the repository.

   Italian by default, English when switched (ADR-0006); every string is in i18n. It must meet the G5 checklist (`docs/VERIFICATION.md` 4a: keyboard, focus, contrast, touch targets, layout at 412x915 and 1280x720) and must not cover the attribution.
3. **The attribution line** names every source whose licence asks for it, at both sizes. Keep "(c) OpenStreetMap contributors" (hard rule 10).
4. **`README.md`:**
   - what the project is, with a screenshot reference (taken from existing evidence, not a third-party page);
   - prerequisites with pinned versions (Python 3.12 and uv; Node and npm versions from the repo);
   - getting the data, with links to `docs/DATA_SOURCES.md`;
   - `make setup`, `make data`, `make tiles` / `make web-tiles EXTENT=pilot|city`, `npm run dev`, `npm run build`, `npm test`, `npm run e2e`, `npm run serve`, and what each produces;
   - the expected time and disk use, measured;
   - the host requirement (brotli, `_headers`; ADR-0038);
   - the licences.
5. **Rebuild check.** Follow the README yourself, step by step, from a fresh clone in a new directory, for the pilot extent (the city if time allows), and record every command and its time. Fix the README wherever it is wrong. The reviewer repeats this at gate G7.

## Decision needed from the owner
The project's own code licence (for example MIT or Apache-2.0) is the owner's choice. Do not pick one. Leave a placeholder section in the README and say so in your report. Data licences come from the sources, not from us.

## Constraints
- **No changes** to the map's look, levels, budgets or the pipeline.
- **Baselines.** The visual baselines may change only where the attribution line or the About control appears. If they do:
  - regenerate them in a separate commit, with before, after and diff images and pixel counts under `reports/artifacts/T-7.2/baselines/`;
  - the owner approves them.
- **No new dependencies.** Do not run whole-file formatters.
- **Ports:** E2E_PORT=4217, serve on 4218. The owner's servers are on 4173 and 4174.
- **Processes:** never stop a process you did not start, and leave nothing running.
- **Commit messages** end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Acceptance criteria
1. **Checks:** `make test`, typecheck, lint, unit tests and build pass; e2e passes twice; there is a new e2e test for the About page (open, keyboard, Escape, language switch, both sizes); the JS budget is still at most 600 KB gzip.
2. **Licences:** the licence-obligation table is in `reports/R-7.2.md`, each row with a URL.
3. **Rebuild log:** the README rebuild log, from a clean clone, is in `reports/artifacts/T-7.2/rebuild.md`.
4. **Records:** your PROGRESS row only; committed on t-7.2; `git status --short` empty; nothing on 4217 or 4218.
