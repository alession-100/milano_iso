# T-7.3b - Can a `_headers` content-type override make Cloudflare compress the `.glb` tiles?

- **Phase / depends on:** Phase 7, after T-7.3a. Owner decision 2026-11-25: try the type override first.
- **Owner:** executor. The owner runs every deploy.
- **Branch:** t-7.3b

## Goal
Find out by measurement whether the tiles can arrive compressed (zstd, brotli or gzip) on Cloudflare Workers static assets when `_headers` gives them a content type that Cloudflare compresses. If they can, apply it and measure the phone payload against 3,000,000 B.

## Background
- **R-7.3a** (https://milano-iso.alessio-narciso1.workers.dev, build dist73 from d49232c):
  - `.glb` tiles are sent as `model/gltf-binary` with no `Content-Encoding`.
  - JSON, SVG and JS are compressed: zstd for a client that offers it, gzip otherwise.
  - `tiles.json` gets the `/tiles/*` immutable value and its own `no-cache` together.
- **Cloudflare's compressed content types** (developers.cloudflare.com/speed/optimization/content/compression/) include `application/json`, `application/wasm`, `image/svg+xml` and `text/*`, but not `model/gltf-binary` or `application/octet-stream`.
- **The client:** it reads tiles with `fetch(...).arrayBuffer()` and parses them as glb; the response's content type does not matter to it. Check this in `web/src/tiles/loader.ts`, and say so if it is not true.

## Phase A - one experimental deploy, several variants at once
1. **Variants.** Copy `scratchpad\dist73` to a new directory outside the repo. In that copy only, add `_headers` rules for single, named tile paths, one variant per tile, at least:
   - a level-0, a level-1 and a level-3 tile set to `Content-Type: application/json`;
   - one tile set to `Content-Type: application/wasm`;
   - one tile set to `Content-Type: text/plain`;
   - one tile unchanged, as the control.

   If the docs allow it, also try the detach syntax (`! Content-Type`) before setting the new value, on one tile. Separately, fix the `tiles.json` rule in this copy so it ends up `no-cache` only, using the detach syntax for `Cache-Control` if needed.

   Cite the Cloudflare Workers `_headers` documentation for the syntax and for whether `Content-Type` may be overridden; write NOT FOUND where the docs say nothing.
2. **Hand over to the owner.** Stop and hand back the exact deploy command for the owner, the same as R-7.3a's but with the new directory. Do not deploy yourself.

## Phase B - after the owner confirms the deploy (the orchestrator will resume you)
3. **Headers.** For every variant tile, record with `curl -sI` and with a full GET: `Content-Type` (single value, or two joined), `Content-Encoding` and bytes on the wire, for `Accept-Encoding: br, gzip, zstd` and for gzip only. Check that the decompressed bytes equal the file's sha256. Report `tiles.json`'s `Cache-Control`.
4. **If a variant compresses the tiles:**
   - Apply it to every `.glb` in `web/public/_headers` with a path rule. If a rule cannot match by extension, say what pattern you use and what else it catches.
   - Apply the `tiles.json` fix too.
   - Rebuild, and update `web/scripts/serve.mjs` and its `_headers` test only if the local server must agree.
   - Hand back a second deploy command for the owner, then stop.
   - After that deploy, run the card T-7.3a payload runs: 412x915 and 1280x720, three runs each, bytes until the default view is complete, against 3,000,000 B.
5. **If no variant compresses:** report the table and stop.
