## Changes
1. **City benchmark.** `?debug=bench` gets a fixed, deterministic city path (for example centre, then outward across levels 0 to 3 and back, at least 60 s) that reports mean fps, 1 % low (or p99 frame time), draw calls and triangles per segment, and which level was drawn. The pilot path stays available (for example `?debug=bench&tiles=tiles/pilot/`). Record the pose sequence in code so every run is the same.
2. **Profiling and tuning.** Profile the city bench (Chromium performance trace with the real GPU on this machine, headed; say how you launched it and which GPU backend was used). Fix what the trace shows (for example per-frame allocations, redundant matrix or material updates, shadow cost at coarse levels, too many small meshes). Every change states its measured before and after. Never change the look at the base level (visual baselines must not change); a look change at coarse levels needs before/after images in the report.
3. **5-minute memory session.** An automated, scripted Playwright session (not part of the default e2e run; its own npm script) that pans and zooms across the city for 5 minutes on the served build (`npm run serve`) and samples every 10 s: JS heap used (`performance.memory` with precise memory info, or CDP `Runtime.getHeapUsage`), `renderer.info.memory` (geometries, textures), programs, tiles loaded, tiles in scene, and DOM node count. Pass rule, stated in the report: after the first minute (warm-up), the last-minute medians are within 10 % of the second-minute medians for the heap, and geometries and textures never exceed what the cache limit allows; force a GC (CDP `HeapProfiler.collectGarbage`) before each sample. Run it twice.
4. **City as default.** `DEFAULT_TILES_BASE` becomes `tiles/city/`; `?tiles=tiles/pilot/` still opens the pilot. `make web-tiles` copies both extents. The e2e fixture setup is unchanged (tests intercept `**/tiles/**`). Update `.claude/launch.json` only if the serve command changes (it currently runs `npm --prefix web run preview` on 4173; prefer adding the served build as a second configuration rather than replacing it).
5. **Budgets table.** `reports/artifacts/T-6.4/budgets.md`: every row of VERIFICATION 5 for the city, measured on this machine (fps with the real GPU, headed; draw calls; payload and JS from T-6.3 re-measured on the final build; time to first render), with the command for each row.

## Constraints
- Budgets: >= 60 fps desktop on the city bench mean (real GPU), <= 300 draw calls everywhere on the bench. Do not lower a budget. The phone target (>= 30 fps on the Pixel 7a) is measured by the owner; you provide the URL and the steps.
- No new dependencies; static only; no runtime third-party requests. Deterministic pipeline (if you touch it, pilot base tiles stay byte-identical and city determinism holds).
- Do not change the palette, heights rules, ranking, the band layout (ADR-0034), level selection thresholds (ADR-0037) or the payload reading (ADR-0038) without escalating.
- Do not run formatters that rewrite whole files. Never leave a server or process running; never stop a process you did not start (the owner's preview is on 4173). Use `E2E_PORT=4190` and serve port 4191.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
