# T-0.3a - Correct the map origin centroid (corrective, retry 1/2 of T-0.3)

- **Phase / depends on:** Phase 0 / T-0.3 (merged), T-0.2 (merged)
- **Owner:** executor
- **Branch:** t-0.3a

## Goal
Fix a floating-point error in the Duomo centroid that put the recorded map origin and pilot AOI 1 m off on each axis. Then freeze the origin as a single constant in pipeline code, with a test that protects it.

## Evidence of the failure (gate G0, blocker B1)
`pipeline/scripts/origin_from_sources.py`, function `ring_area_centroid`, applies the shoelace formula to raw EPSG:32632 coordinates (about 5e6 m). Cancellation shifts the centroid by about 0.27 m in northing:

| Method | E | N |
|---|---|---|
| script, raw coordinates (recorded) | 514978.4830 | 5034535.3075 |
| same function after subtracting the first vertex | 514978.5109 | 5034535.5807 |
| exact rational arithmetic (`fractions.Fraction`) | 514978.5109 | 5034535.5807 |
| shapely `Polygon.centroid` (orchestrator re-check) | 514978.5109 | 5034535.5807 |

So the rounded origin should be E 514979, N 5034536, not E 514978, N 5034535. Every figure derived from the centroid in `docs/DATA_SOURCES.md` is wrong as written: centroid in WGS84 and EPSG:32632, distance to Wikidata, origin, AOI bbox and AOI corners.
