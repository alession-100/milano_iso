# T-4.4 - Platform-independent markings (CI fix)

- **Phase / depends on:** Phase 4 follow-up / G4. Done by the orchestrator as a narrow fix; CI on Linux is the independent check.
- **Branch:** t-4.4

## Evidence
CI (Linux) failed `test_fixture_regenerates_byte_identically` on `-1_-1.glb` from 675f1cc onwards (log pasted by the owner on 2026-11-17).
- The diff is confined to the `markings` mesh: the same dash vertices in reverse order, and two rectangles triangulated on the other diagonal.
- Cause: markings are computed with buffer, interpolate and union. Linux and Windows GEOS builds differ in the last bits of those results, which changes the order of union parts and the diagonal Delaunay picks for a rectangle, since all four corners lie on one circle.
- The G4 review's statement that the stale Linux baselines were the only CI issue was wrong; it could not run Linux.

## Change
- In `decor.build_markings`, snap each marking geometry to a 1 mm grid (`MARKING_GRID_M`, numeric precision, not style), normalise every part, and sort the parts canonically.
- Add two tests:
  - output identical under ±1e-9 m input shifts, a stand-in for platform float noise;
  - coordinates on the 1 mm grid.
- Both tests fail without the fix and pass with it.
- Regenerate the fixture.

## Acceptance
- `make test` exits 0, and the full e2e (40, including 12 visual) passes against the approved baselines.
- CI is green on Linux.
