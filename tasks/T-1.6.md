# T-1.6 - Data validation suite on the real processed data (VERIFICATION section 3)

- **Phase / depends on:** Phase 1 / T-1.4a (merged)
- **Owner:** executor
- **Branch:** t-1.6

## Goal
A single command, `make validate`, that checks the real processed pilot data against every applicable item in `docs/VERIFICATION.md` section 3, plus a command that checks the pipeline is deterministic. The reviewer uses these at gate G1.

## Inputs
- `CLAUDE.md`
- `docs/VERIFICATION.md` section 3
- `docs/DECISIONS.md`: ADR-0004, ADR-0011, ADR-0013, ADR-0014, ADR-0015, ADR-0016 only.
- `pipeline/milano_iso/` (read only, except a shared helper if needed), `pipeline/mk/*.mk`, `tests/`, `tests/landmarks.yaml`
- `reports/artifacts/T-1.3/validation.json`, `reports/artifacts/T-1.4/*`
- Data: `processed/pilot.gpkg`, `interim/*.gpkg` (shared cache)

## Outputs
- `tests/data/` : pytest tests marked `@pytest.mark.data` that read the real processed data. These tests are **not** collected by `make test`: configure the marker so `make test` deselects them.
- `pipeline/mk/90-validate.mk`, with two targets:
  - `validate`: runs `pytest -m data` and writes a JUnit XML plus a Markdown summary to `reports/artifacts/T-1.6/`.
  - `check-determinism`: runs every `DATA_STEPS` step twice from the interim/processed outputs (downloads skipped) and compares the canonical sha256 of every produced GeoPackage. It prints both hashes and exits non-zero on any difference.
- `reports/artifacts/T-1.6/validate_summary.md`, `landmarks_check.csv`
- `reports/R-1.6.md`

## Checks (each one is its own test with a clear failure message)
1. **CRS:** every layer in `processed/pilot.gpkg` is EPSG:32632.
2. **Geometry:** every geometry is valid and non-empty. There are no zero-area polygons and no zero-length lines. There are no exact duplicates (same key and same geometry) in any layer.
3. **Extent:** every feature intersects the pilot extent, except DBT volumes whose building intersects it (ADR-0013 as amended in T-1.4).
4. **Completeness (ADR-0014):**
   - DBT: the volumes in `render_volumes` with source dbt, divided by all volumes of the selected DBT buildings in the source ZIP, is >= 99%. Compute the denominator from the source, independently of `normalise.py`.
   - OSM: the OSM buildings either matched or present in `buildings`, divided by the `building=*` areas in `interim/osm_pilot.gpkg`, is >= 99%.
   - Every dropped feature appears in the T-1.3 drop log with a reason.
5. **Heights:**
   - Every `buildings` and `render_volumes` row has `height_m > 0` and `height_source` in {dbt, osm_height, osm_levels, default}.
   - The test writes the distribution and the share per source to the summary.
   - Outliers (> 250 m or < 2 m) are listed with keys. Listing them is not a failure; their presence is reported.
   - The baseline share of explicit (non-default) heights is printed, by count and by footprint area. The threshold is fixed later by ADR, so this is reported, not asserted.
6. **Sanity:** the tallest building is <= 250 m. Print its key, name and height for the reviewer to check against a cited source.
7. **Landmarks:** for every `tests/landmarks.yaml` entry with `in_pilot: true`:
   - **(a) Pipeline integrity:** the centroid of the processed OSM footprint with the same OSM type and id (in `osm_buildings`, or another layer if the element is not a building) is within `tolerance_m` of the reference position.
   - **(b) Rendered position:** the rendered building whose `landmark_id` equals the entry id is checked the same way. Its footprint centroid is the union of its rendered volumes' footprints, or of its OSM footprint if it is OSM-only. It must be within `tolerance_m`.
   - Write both distances for every entry to `landmarks_check.csv`. A failure in (b) is a real finding: do not loosen it. Report it.
   - A landmark with no rendered building (for example `rendered = false`) fails (b) with that reason, unless it is the Galleria roof, which ADR-0016 explicitly defers to Phase 4. In that case it must be reported as `deferred_phase4`, not as passed.
8. **Simplification:** not applicable before tile export. The test is skipped with the reason "applies at tile export, Phase 2".

## Acceptance criteria
1. `make validate` runs all checks and writes the summary. Report the exact pass/fail/skip counts. Failures must be real findings with evidence, never suppressed.
2. `make check-determinism` exits 0 and prints matching hashes for every produced GeoPackage.
3. `make test` still exits 0 and collects no data tests: show its count, unchanged from before.
4. Sabotage checks, run in a scratch copy of `processed/pilot.gpkg` with an env override, never on the real file:
   - set one `height_source` to null: `make validate` fails;
   - move one landmark footprint by 10 m: the landmark check fails.

   Show both runs, then confirm the real data is untouched (its sha256 is unchanged).
5. `git status --short` empty; committed on `t-1.6`.
