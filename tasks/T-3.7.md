- **Phase / depends on:** Phase 3 follow-up / G3 passed. The owner approved palette v1 on 2026-11-17.

- **Branch:** t-3.7

## Goal
Make the visual-regression check sensitive enough to catch visible style changes, before the approved look is stored as baselines. Let CI produce the Linux baselines through a manual workflow, so the CI skip can be removed.

## Evidence (G3 re-review, non-blocking issues 1 and 2)
- With only `maxDiffPixelRatio: 0.01` and Playwright's default per-pixel `threshold` 0.2, darkening the ground from 0xe3ded4 to 0xd3cec4 passes 6/6, although the change is clearly visible.
- `buildingResidential` set to 0xff00ff passes 6/6, because the fixture holds only `building_type: "yes"`.
- The 412x915 wide view barely shows buildings.
- Repeat-run noise on this machine was 0 px over 30 captures.

## Changes
1. **Fixture.** Extend the synthetic fixture so its buildings cover every building colour group in `web/src/style/palette.ts`: residential, commercial/office, civic/religious, industrial, other, and one with a `landmark_id`. Also include each flat layer that has its own colour. Regenerate it through the real exporter. Update the expected counts in the existing specs, and keep the byte-identical regeneration test passing.
2. **Threshold.** In `playwright.config.ts`, set an explicit per-pixel `threshold` (start at 0.02) together with `maxDiffPixelRatio` (keep 0.01, or lower it if measured noise allows).
   - Measure the noise again with `--repeat-each=5`.
   - Prove sensitivity with sabotage runs in a scratch working copy. Each one must fail on at least 1 view:
     - (a) ground 0xe3ded4 to 0xd3cec4;
     - (b) each building group colour shifted by 16 levels in one channel, one run per group;
     - (c) road colour shifted by 16 levels.
   - Revert every sabotage and show `git status` clean.
3. **Views.** Make sure each building group is visible in at least one desktop and one mobile view; add a fourth view if needed.
4. **Baselines.** Regenerate the win32 baselines from the extended fixture. In the snapshots README, replace the date `PENDING` with: "The owner approved palette v1 on 2026-11-17 (Phase 3 checkpoint); baselines regenerated in T-3.7".
5. **CI Linux baselines.** Add `.github/workflows/visual-baselines.yml`, run only by `workflow_dispatch`. It builds the web app, runs `npx playwright test e2e/visual.spec.ts --update-snapshots`, and uploads the `*-linux.png` files as a workflow artifact (`actions/upload-artifact` pinned by full commit SHA), with `permissions: contents: read`. Use the same pinned actions and versions as `ci.yml`. Do not make it push commits.
   - Document in the README: run the workflow, download the artifact, commit the PNGs, then remove the CI skip.
   - Leave the skip in place for now.
