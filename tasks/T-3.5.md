# T-3.5 - Integrate camera controls (T-3.1) with tile streaming (T-3.2)

- **Phase / depends on:** Phase 3 / T-3.1 (on main), T-3.2 (branch `t-3.2`, not yet merged)
- **Owner:** executor
- **Branch:** t-3.5

## Goal
Merge branch `t-3.2` into a new branch cut from `main` (which already holds T-3.1), resolve the conflicts, and wire the two together into one viewer: the controls drive the camera, and tile culling and attribution follow it.

## Known conflicts (orchestrator dry run)
- **`web/src/main.ts`:**
  - T-3.1 renders on demand: `requestRender()` coalesces into one `requestAnimationFrame` and there is no permanent loop.
  - T-3.2 runs a permanent `requestAnimationFrame(frame)` loop that compares a camera key every frame.
  - T-3.2 also places the camera with the temporary `tiles/tempview.ts` (`?view=`).
- **`web/src/i18n.ts`:** both added keys (`mapLabel` vs `dataLabel`, `tilesError`). T-3.2 also removed the `attribution` placeholder key.

## Required result
1. **One render model: on demand.** Keep T-3.1's `requestRender()` (no permanent loop).
   - Every camera change calls `requestRender()` (controls, inertia, resize).
   - So does every tile load or evict, and every manifest load.
   - Inside the frame callback: if the camera changed since the last cull, run `updateTiles()`; then render and record `renderer.info` into the `render` test state.
   - Inertia animation is driven by the controls' own frames, which call `requestRender()`.
2. **Remove `web/src/tiles/tempview.ts`** and every use of it (`fitCamera`, `?view`). The `CameraRig` owns camera placement and resize.
   - For tests and measurements, add an e2e-only camera setter instead: with `e2e=1`, expose `window.__milanoIsoSetView?.(x, z, width)` through `testhook.ts` (or an equivalent documented helper), calling the rig.
3. **Bounds:** once the manifest loads, call `rig.setBounds(contentBounds(manifest))`, with `contentBounds` from `tiles/manifest.ts`. Add an e2e test that dragging far beyond the content clamps.
4. **i18n:** keep `mapLabel`, `dataLabel` and `tilesError`, and drop the old `attribution` placeholder key. `it`/`en` key parity stays tested.
5. **Console filter:** both specs use the single helper in `web/e2e/support.ts` (ADR-0012 as amended). `controls.spec.ts` must not keep its own copy.
6. **Port:** the e2e preview stays on 4173 (runs are sequential; no change needed unless you find a real collision).
