## Inputs

- `web/src/layout.ts` (`fit()`), `web/src/toolbar.ts` (~line 125, `scrollIntoView`), `web/src/debug.ts`, `web/e2e/layout.spec.ts`, `web/playwright.config.ts`, `.github/workflows/ci.yml` (read only unless item 3 needs it)
- Third G5 review findings:
  - **N8 (medium).** `fit()` resets the panel's `maxHeight` to its natural 220 px before setting the smaller value; that clamps `scrollTop` and undoes `scrollIntoView` in `toolbar.ts`. Changing the active option fires the MutationObserver (`class`), so the reset runs on every arrow press. With query "via": at 640x412 with the card open (list 136 px) option 7 shows 5 of 44 px and option 8 shows 0; at 360x360 without card option 8 shows 0; at 640x412 without card option 8 shows 31. 1280x720 and 412x915 are unaffected. Sighted keyboard users lose sight of the active option (WCAG 2.4.11).
  - **N9 (low, `?debug` only).** With `?debug`, card + layers: at 700x600, 700x412 and 700x915 the card's close button is covered by `#layer-trees` (card [100,108,400,288] vs panel [6,56,366,322]); below 700 px wide the overlay shrinks the area so the panel overflows the zone's max-height (412x412: zone ends at 120, panel at 150). 18 of 32 debug audits failed. ADR-0034 says the overlay is laid out above the band.
  - **CI wall time.** `layout.spec.ts` has 26 tests that run one after another on one worker (about 21-22 s each idle, 1.4-1.5 min under load); the full suite is 9.2 min idle on a 20-core machine and 34.5 min under load. CI runners have 2-4 cores.

## Changes
1. **N8.** `fit()` must not disturb the scroll position of a list it constrains, and must not run its reset on attribute changes that do not change size (for example observe only what can change the available height, or compute the new max-height without first restoring the natural one). Keep the active option fully visible after each arrow press. e2e: with query "via" at 640x412 with the card open and at 360x360, press ArrowDown through all 8 options and assert each active option is fully inside the list's visible box (poll until settled; no wall-clock thresholds).
2. **N9.** Lay out the `?debug` overlay so it never covers or squeezes the zone or the card: for example in the band's area above the attribution, or collapsed to one line at compact sizes. Add `?debug` to a small part of the layout sweep (a few widths x heights x the card + layers state).
3. **Wall time.** Make `layout.spec.ts` run in parallel (e.g. `test.describe.configure({ mode: 'parallel' })`) or split it so no single worker carries the whole sweep, without weakening it. Report the full-suite time on this machine at default workers and with `--workers=2` (an approximation of a CI runner). If `--workers=2` exceeds 30 min, say so.
4. **Checks.** The win32 visual baselines must not change (run `visual.spec.ts` and `toolbar.spec.ts` without `--update-snapshots`).
