## Changes
1. **Attribution band.**
   - The attribution sits in a bottom band whose height follows its real wrapped height (measure it, e.g. with a ResizeObserver feeding a CSS variable; no fixed pixel guesses).
   - Every other UI block (toolbar panels, results list, layers and help panels, the tile notice, the minimap, the card, the right-hand controls, the `?debug` overlay) is laid out in the area above the band. Where space is short, it scrolls inside itself (max-height from the available area), or collapses. It never extends into the band.
   - Keep the T-5.5 roomy/compact rule otherwise; record the band rule in ADR-0032 (amend) or a new ADR-0034.
2. **Notice.**
   - Hide the tile notice only where there is truly no room. When it must yield, keep its text in a polite live region, so its arrival is still announced.
   - Prove the announcement content in e2e (the live region's text changes while a panel is open).
3. **Card at 360 px wide** (N1b): the card and the panels share space by the same rule; no overlap at 360-380 px wide for any height.
4. **Sweep.** Extend `layout.spec.ts`:
   - widths 360 to 1440, step at most 40 px, plus 599, 600, 699, 700, 701;
   - heights 360, 375, 390, 412, 480, 540, 599, 600, 640, 728, 915, 1024 (a grid, not only named sizes);
   - in the states card + results + notice, card + layers + notice, card + help + notice, and minimap open + notice;
   - each state also without the card;
   - Italian and English (longer strings).
   - Assert pairwise no overlap, everything inside the viewport, no horizontal scroll, and `elementFromPoint` at the centre and the 4 inset corners of every attribution link returns the link.
   - Keep the run time reasonable: one page per size, switch states in-page, and report the suite time.
   - Prove the sweep catches the bug: with the T-5.5 `index.html`, it must fail at 600x412 and 640x360 (report this).
5. **N7.** Rewrite the reduced-motion inertia test with the CDP-timestamped drag. Prove it fails with reduced motion handling switched off: run `--repeat-each=10` with the mutation and report the count.
6. **Search count.** The status reflects the real number of matches and the number shown (e.g. "8 di 14 risultati" / "8 of 14 results"), with a correct singular in both languages. i18n tests stay green.
7. **Visual baselines.** Regenerate only the win32 baselines that changed; prove map pixels outside UI boxes are unchanged (`web/scripts/compare-baselines.mjs`). Leave `*-linux.png` alone.
