## Changes
1. **Best-fit offset check (ADR-0020).** In `tests/data/`, add the check as specified in ADR-0020 for every in-extent rendered landmark.
   - Write `best_offset_e`, `best_offset_n`, `best_offset_m`, `best_overlap_ratio` and `plateau_width_m` to `landmarks_check.csv`.
   - Put the search in a small, unit-tested function (a synthetic square shifted by a known vector must be recovered within 0.25 m).
   - The ADR-0018 filled-union distance stays reported but is no longer asserted.
2. **Raised-only DBT buildings (G1 finding 3, `EDIFC_2671`: a single `POR` 04 underpass-ceiling volume rendered solid from 0 m).**
   - For a building with no `POR` 01 volume, `ground_z` becomes the median `base_z_min_m` of the `POR` 01 volumes of other buildings within 50 m of its footprint (at least 5 volumes; otherwise widen to 100 m; if there are still fewer than 5, fail loudly).
   - Record this as `ground_flag = "neighbour_median"` with the neighbour count. Update the unit test for the old `no_por01` behaviour.
   - This amends ADR-0015 (the orchestrator updates the ADR text).
   - Report EDIFC_2671's new `bottom_m` and `top_m`. The reviewer estimated about 3.4 and 19.3 m: report your numbers, do not aim for these.
3. **DBT building with no IS footprint.** The source has 170 `EDIFC_CR_EDF_IS` footprints for 171 EDIFC records.
   - When a DBT building has volumes but no IS footprint, `normalise.py` must still produce a `dbt_buildings` row from its `ME` footprint (or the union of its volumes if ME is missing) with `footprint_source` in {is, me, volumes}.
   - Log it in the drop log with action `substituted`.
4. **Duplicates (G1 finding 6).** The data test and `normalise.py` also flag same-geometry, different-key rows per layer.
   - `named_features` is exempt, because admin relations share geometry legitimately; document the exemption in the test.
   - Report the counts.
5. **Cosmetics.**
   - Normalise `-0.0` to `0.0` in numeric outputs.
   - All artifact writers use `newline="\n"`.
   - `reports/artifacts/T-1.6/junit.xml` is gitignored and untracked. `validate_summary.md` contains no timestamps or absolute paths, so a `make validate` run leaves the tree clean.
