# T-1.1 - Fetch and extract OSM for the pilot AOI, plus the comune boundary

- **Phase / depends on:** Phase 1 / G0 passed
- **Owner:** executor
- **Branch:** t-1.1

## Goal
Download a fixed OSM snapshot and the Comune di Milano boundary. Record their checksums, and extract every OSM object that intersects the pilot AOI, with all tags, into one GeoPackage.

## Inputs
- `CLAUDE.md`
- `docs/DECISIONS.md`: ADR-0004 (origin, pilot AOI), ADR-0009 (licences), ADR-0013 (data layout and step conventions). Read these ADRs only.
- `docs/DATA_SOURCES.md`, rows 1 and 4a only (URLs, sizes).
- `pipeline/milano_iso/config.py` (`PILOT_AOI_BBOX`, EPSG:32632)
- `Makefile`, `pyproject.toml`, `tests/pipeline/` (conventions)

## Outputs
- `pipeline/milano_iso/fetch.py`: a generic, idempotent download helper. It streams to `data/raw/<source>/`, computes sha256, and writes or verifies `pipeline/manifests/<source>.json`. Generic User-Agent `milano-iso-pipeline/0.1`, no personal data.
- `pipeline/milano_iso/osm_extract.py`: `python -m milano_iso.osm_extract --extent pilot`. It also accepts `--extent city`, which uses the comune boundary; `city` must work but is not run here.
- `pipeline/manifests/osm_geofabrik.json`, `pipeline/manifests/comune_boundary.json`
- `pipeline/mk/10-osm.mk`: targets `data-osm` and `data-boundary`, appended to `DATA_STEPS`.
- `tests/pipeline/test_fetch.py`, `tests/pipeline/test_osm_extract.py`
- `reports/artifacts/T-1.1/`: run log and summary counts (JSON)
- `reports/R-1.1.md`

## Specification
- **OSM snapshot:** the dated Geofabrik file `https://download.geofabrik.de/europe/italy/nord-ovest-261114.osm.pbf`, not `-latest`, so the build is reproducible. Also fetch the provider's published checksum file next to it (Geofabrik publishes `.md5` files), and check the download against it before writing the manifest.
- **Comune boundary:** the GeoJSON URL in DATA_SOURCES row 4a, saved as `data/raw/comune_boundary/confine.geojson`.
- **Extraction** with pyosmium (`osmium` on PyPI; pin an exact version and add it to `pyproject.toml` and `uv.lock`. It is the only new dependency allowed).
  - Read the PBF once with node locations and area assembly. Keep every object whose geometry intersects the extent polygon: points (tagged nodes), lines (ways that are not areas), and areas (closed ways and multipolygon relations).
  - The pilot extent is `PILOT_AOI_BBOX` (EPSG:32632) transformed to EPSG:4326. Densify its edges before transforming (at least 10 points per edge).
  - Keep each object whole; do not cut it at the extent edge.
  - Output `data/interim/osm_pilot.gpkg` in EPSG:4326, with layers `points`, `lines` and `areas`. Columns: `osm_type` (n/w/r), `osm_id` (int), `area_from` (way/relation, for areas), `tags` (JSON string, keys sorted), plus geometry.
  - Rows are sorted by (osm_type, osm_id) so the output is deterministic.
  - Untagged objects and ways that only belong to a relation are not output on their own.
- Log the counts of objects seen, kept, and failed area assembly (with IDs) to `reports/artifacts/T-1.1/summary.json`. Failed assemblies must be listed, not hidden.
- **Unit tests** use small synthetic data built in the test (for example a tiny `.osm` XML written to `tmp_path`). They must not use the real download. Cover: the fetch helper's skip, verify and mismatch paths (serve files from `tmp_path` with a `file://` URL or a monkeypatched opener); extent intersection; whole-object keeping; area output for closed ways and multipolygons; deterministic ordering.

## Constraints
- All data paths derive from `milano_iso.config` (`DATA_DIR`, `RAW_DIR`, `INTERIM_DIR`, `PROCESSED_DIR`); never hardcode `data/`. Run with `export MILANO_ISO_DATA=C:/Users/studi/Documents/milano-iso/data`, a shared cache across worktrees. Write only inside your own source subfolders.
- Raw data is never committed (`data/` is gitignored).
- Do not edit `Makefile` itself; use the fragment. Do not edit `docs/`.
- `make test` must stay fast (< 60 s). Tests that touch the real data must not run in `make test`.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Out of scope
- Classifying features into buildings/roads/etc., reprojection to EPSG:32632, geometry repair (T-1.3).
- DBT, Overture, landmarks.

## Acceptance criteria
1. `make data-osm data-boundary` downloads, verifies and extracts. A second run makes no download (log shows "skip, sha256 ok") and produces a byte-identical `osm_pilot.gpkg`, or, if GeoPackage is not byte-stable, identical sha256 of a canonical dump (sorted rows as JSON). Show the hashes.
2. The manifests contain url, retrieved_utc, bytes, sha256 (and md5_verified true for Geofabrik).
3. `summary.json` reports counts per layer and lists failed area assemblies (an empty list is fine).
4. Sanity check: the extract contains the OSM relation 18017026 (Duomo, in layer `areas`). Show the query.
5. `make test` exits 0 with the new tests.
6. `git status --short` is empty; work committed on `t-1.1`.

## Verification commands
```bash
make setup
make data-osm data-boundary 2>&1 | tail -20
make data-osm 2>&1 | grep -i skip
cat pipeline/manifests/osm_geofabrik.json pipeline/manifests/comune_boundary.json
cat reports/artifacts/T-1.1/summary.json
uv run python -c "import geopandas as g; a=g.read_file('data/interim/osm_pilot.gpkg', layer='areas'); print(len(a), a[(a.osm_type=='r')&(a.osm_id==18017026)][['osm_type','osm_id']])"
make test
git status --short
```

## Escalate if
- The dated Geofabrik file is no longer available, or its md5 does not match.
- pyosmium cannot be installed for Python 3.12 on Windows or Linux.
- Extraction takes longer than 30 minutes or needs more than 8 GB of RAM.
