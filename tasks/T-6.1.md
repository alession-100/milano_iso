## Goal
Run the whole pipeline (`make data`, `make tiles`, `make validate`) on the comune di Milano boundary, reproducibly, and measure wall time and peak memory per step. Partition the work only if a measured step needs it. The pilot build must not change.

- `Makefile`, `pipeline/mk/*.mk`, `pipeline/milano_iso/` (all steps; `osm_extract.py` already has `--extent city` via `city_extent_wgs84()`; `dbt_extract`, `normalise`, `heights`, `decor` accept only `pilot`; `tiles/export.py` has `--extent` with default `pilot`), `pipeline/manifests/*.json`, `tests/`
- Raw downloads already on this machine (do not download again): copy `C:\Users\studi\Documents\milano-iso\.claude\worktrees\agent-a6736ef53cb2c6ee2\data_t56\raw` into your own data dir and point `MILANO_ISO_DATA` at it. The fetch steps verify sha256 against the manifests.
- Pilot reference tiles for the regression check: `...\agent-a6736ef53cb2c6ee2\data_t56\tiles\pilot` (built from main before this task).

## Outputs
- Every step accepts `--extent pilot|city`; the Make fragments take it from one variable, `EXTENT ?= pilot` (so `make data tiles validate` alone still builds the pilot exactly as today, and `make data tiles validate EXTENT=city` builds the city).
- Per-extent paths: `interim/osm_<extent>.gpkg`, `interim/dbt_<extent>.gpkg`, `processed/<extent>.gpkg`, `tiles/<extent>/`, and per-extent report artefacts (do not overwrite the committed pilot artefacts under `reports/artifacts/T-1.*`..`T-4.*` with city numbers; city artefacts go to `reports/artifacts/T-6.1/`).
- The city extent is the comune boundary from `raw/comune_boundary`, reprojected to EPSG:32632, with ADR-0013's rule (kept when intersecting, kept whole). The tile grid stays the 250 m grid of ADR-0021 with the same origin.
- A measuring wrapper (a small script under `pipeline/`, standard library plus what is already a dependency) that records wall time and peak resident memory of each step; results in `reports/artifacts/T-6.1/measurements.json` (step, extent, seconds, peak MB, row/feature counts in and out).
- `reports/artifacts/T-6.1/city_summary.md`: feature counts per layer, number of tiles, total tile bytes raw and gzip, tile size distribution (min, median, p95, max gzip), the count and ids of tiles above the 250 KB gzip budget, `index.json` size raw and gzip, drop-log totals by reason.
- An ADR (next free number) for the extent parameter and any partitioning.
- `reports/R-6.1.md`.

## Constraints
- Deterministic (hard rule 5): two city builds give byte-identical tiles. Any new geometry computed with trig, buffer, interpolate or union is snapped and sorted (CLAUDE.md lesson).
- Partition (for example by tile column or by a grid of blocks, processed one at a time and merged in sorted order) **only** if a step's measured peak memory exceeds 24 GB or a step does not finish in 2 h. If you partition, a partitioned build and an unpartitioned build of the pilot must be byte-identical.
- The pilot outputs must not change: `make tiles` (default pilot) gives files byte-identical to the reference tiles above, and the pilot validation tests pass unchanged.
- No new dependencies. Do not edit `web/` (serving the city in the client is T-6.2/T-6.3). Do not change palette, heights rules, decor rules or ranking.
- Raw and built data are never committed (hard rule 7). Long runs go in the background; never leave a process running at the end.
- Do not run formatters that rewrite whole files beyond `ruff format` on the files you touched.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Out of scope
- LOD, streaming, compression headers, client performance (T-6.2 to T-6.4).
- Making `make data` incremental, unless a step cannot otherwise be measured; if you do it, say so in the report.
- Fixing data defects found in the city (list them in the report with counts and examples instead).

## Acceptance criteria
1. `make test` passes (lint, pytest, typecheck, vitest); new tests cover the extent parameter (the `pilot` and `city` extent polygons, path derivation) and partitioning if present.
2. `make data tiles EXTENT=pilot` gives tiles byte-identical to the reference pilot tiles (report the file count and the comparison command output).
3. `make data tiles validate EXTENT=city` completes end to end; `measurements.json` and `city_summary.md` are written from that run (numbers copied from script output, never estimated).
4. City determinism: `check-tiles-determinism` (or its city equivalent) shows byte-identical tiles across two builds; report the command and output.
5. Every landmark of the landmark yaml is resolved in the city build exactly as in the pilot (same ids).
6. `git status --short` empty; committed on `t-6.1`; `reports/R-6.1.md` written with the time and memory table.


## Escalate if
- A step exceeds 24 GB peak or 2 h and partitioning would change the output semantics (for example features kept whole across partitions).
- The comune boundary raw file is not usable as the extent, or a city input is missing from the raw downloads.
- Any pilot output changes and you cannot make it byte-identical again.
