## Changes
1. **Manifest at start.** The client must not need a 675 KB manifest before the first frame. For example: a small root manifest (format, origin, levels, attribution, extent) plus per-level or per-block manifests fetched on demand; or a compact encoding. Keep the committed JSON Schema in step and validated. The pilot base tiles stay byte-identical.
2. **Precompression.** A build step writes `.br` (Node's built-in `zlib.brotliCompressSync`) and `.gz` next to every text and glb asset of `web/dist` and `web/public/tiles/<extent>` that gets smaller; deterministic (fixed quality and window; no timestamps in gzip headers).
3. **Serving and caching.** A dependency-free local static server (`web/scripts/serve.mjs`, Node built-ins only, bound to 127.0.0.1) that serves the built site with content negotiation (`Accept-Encoding` br, then gzip), correct `Content-Type` and `Content-Encoding`, `Vary: Accept-Encoding`, and cache headers: hashed JS/CSS `immutable`; tiles revalidated or versioned by the manifest's sha256 (your choice, in the ADR); `index.html` and the root manifest `no-cache`. Add `npm run serve`. Write the same header rules as a host-neutral file (for example `web/public/_headers`) and say in the ADR which hosts honour it; do not deploy.
4. **Streaming.** Requests for tiles that are no longer wanted (left the view or replaced by another level before they arrived) are cancelled with `AbortController` and never added to the scene; the concurrency limit and nearest-first order hold across levels; a cancelled tile can load again later. Report the cache limit and why it fits.
5. **Measurements** (`reports/artifacts/T-6.3/measurements.md`, numbers from script output), served by `npm run serve`, Playwright Chromium, cold cache, at 1280x720 and 412x915, city tileset:
   - Initial payload: all bytes on the wire until the default view (origin, 600 m) is complete, split by type (HTML, JS, manifest, minimap, tiles, other). Budget <= 3 MB.
   - JS bundle gzip and brotli (budget <= 600 KB gzip).
   - Time to first render and to complete view with network throttled to a fast connection (state the profile, for example 40 Mbit/s down, 20 ms RTT, via CDP). Budget <= 3 s to first render.
   - A scripted pan and zoom path (at least 20 steps across levels) that counts requests started, cancelled and completed, and bytes wasted on cancelled ones.
   - The same bytes measured with br and with gzip, so the Python/Node zlib difference is visible.

## Constraints
- Static files only; no backend; no third-party requests at runtime (the e2e console and network checks must still pass).
- No new dependencies (pipeline or web). Do not edit the palette, heights rules, ranking, the band layout or level selection (ADR-0037) beyond what cancelling needs.
- Deterministic outputs (pipeline and precompressed files). Visual baselines must not change.
- Do not run formatters that rewrite whole files. Never leave a server or process running. Use `E2E_PORT=4188` and a serve port of 4189.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Acceptance criteria
1. `make test`, web typecheck, lint, unit tests and build pass; full e2e passes twice (report the time). New tests: manifest split (pytest and vitest), precompression determinism, server negotiation and headers (vitest or a node test), cancellation (vitest, and one e2e on the fixture).
2. Pilot base tiles byte-identical to the T-6.2 reference; city determinism holds (`check-tiles-determinism EXTENT=city`).
3. Initial payload <= 3 MB and first render <= 3 s on the stated profile at both viewport sizes; JS <= 600 KB gzip. If a budget is missed, report the numbers and stop (do not lower it).
4. The pan/zoom path shows every unwanted in-flight request cancelled and no cancelled tile in the scene.
5. `git status --short` empty; no server on 4188 or 4189; committed on `t-6.3`; ADR (next free number) and `reports/R-6.3.md` written.
