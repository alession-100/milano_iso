# T-1.5 - Landmark reference file with cited positions

- **Phase / depends on:** Phase 1 / G0 passed. Runs in parallel with T-1.1 and T-1.2.
- **Owner:** executor
- **Branch:** t-1.5

## Goal
Create `tests/landmarks.yaml`: the reference positions of the project's landmarks. Every value is derived by a committed script from saved responses of OSM and Wikidata, and every entry has a citation.

## Inputs
- `CLAUDE.md`
- `docs/DECISIONS.md`: ADR-0004 (origin, AOI), ADR-0011 (landmark position definition and extent flags), ADR-0013 only.
- `pipeline/milano_iso/config.py`, `pipeline/milano_iso/geo.py`
- `tests/pipeline/` (conventions)

## Landmarks
Find each one by name; never type a QID or coordinate from memory.

- **Phase 4 landmarks:** Duomo di Milano, Castello Sforzesco, Torre Velasca, Grattacielo Pirelli, Bosco Verticale (each of its two towers), Stazione di Milano Centrale (the station building), the three CityLife towers (Torre Allianz/Isozaki, Torre Generali/Hadid, Torre PwC/Libeskind), Stadio Giuseppe Meazza (San Siro).
- **Pilot-area references, for checking positions in the pilot:** Galleria Vittorio Emanuele II, Teatro alla Scala, Palazzo Reale, Palazzo Marino, Palazzo delle Assicurazioni Generali (Piazza Cordusio).

## Method
1. For each landmark, find its Wikidata QID with the Wikidata search API (`wbsearchentities`, language it/en). Confirm the label and description, and save the response.
2. Fetch the entity JSON, including P625 if present.
3. Find the OSM element tagged `wikidata=<QID>` with Overpass. If there are several, pick the building footprint (`building=*` or the `building:part`-free outline) and explain the choice.
4. Fetch that element's full geometry from the OSM API: `/api/0.6/{way|relation}/<id>/full`, or the node itself. Record its version and timestamp.

Use a generic User-Agent `milano-iso-landmarks/0.1`, at most 1 request per second, with no personal data. Save every response to `reports/artifacts/T-1.5/responses/`.

## Outputs
- `pipeline/scripts/build_landmarks.py`: offline. It reads only the saved responses and writes `tests/landmarks.yaml` deterministically, with sorted keys and entries sorted by id. Centroids use the numerically stable `milano_iso.geo` method or shapely; cross-check that they agree within 1e-3 m.
- `tests/landmarks.yaml`. Each entry has:
  - `id`: a slug.
  - `name`.
  - `wikidata`: the QID.
  - `osm`: type, id, version, timestamp.
  - `position`: `e`, `n` in EPSG:32632 to 0.01 m, `lat`, `lon` to 7 decimals, and `method: footprint_centroid | node`.
  - `in_pilot`: computed with `PILOT_AOI_BBOX`.
  - `wikidata_p625`: lat, lon, and `distance_m` to the position (null if absent).
  - `tolerance_m: 5`.
  - `sources`: the URLs used, with retrieval date.
- `tests/pipeline/test_landmarks_file.py`. It checks:
  - the schema of every entry;
  - unique ids and QIDs;
  - that `in_pilot` matches the bbox for every entry;
  - that positions fall inside the comune's rough extent (the Comune boundary is not available on this branch, so use the bbox of all landmark positions only to check that no entry is more than 20 km from the origin);
  - that running `build_landmarks.py` reproduces the committed YAML byte for byte.
- `reports/artifacts/T-1.5/`: responses, plus `choices.md` explaining every non-obvious element choice.
- `reports/R-1.5.md`

## Escalate if
- A landmark has no Wikidata item, or no OSM element carries its QID.
- The OSM element for a landmark is ambiguous and the choice changes the position by more than 20 m.
- An API blocks access. Do not work around blocks.
