# T-7.0 - Choose the static host: cited limits and brotli support for three hosts

- **Phase / depends on:** Phase 7, first card. Owner decision 2026-11-24: research hosts before deploying. Research only.
- **Owner:** executor (research)
- **Branch:** t-7.0 (report and ADR proposal only)

## Goal
The owner can choose a host from cited facts. The question is which free static host can serve the city build within its limits, with our precompressed brotli files and our cache headers.

## Background
- **ADR-0003:** GitHub Pages, with a stated risk on headers and size. If needed, the fallback is a free CDN-backed host (new ADR; anything paid needs owner approval under ADR-0008).
- **ADR-0038:**
  - The phone default view is 2.48-2.57 MB with brotli but 4.44-4.63 MB with gzip only, against a budget of 3,000,000 B. The host must serve `.br` with `Content-Encoding: br`, either from our precompressed files or by compressing on the fly with brotli.
  - `public/_headers` states the cache rules.
- **R-0.3:** GitHub Pages site size, bandwidth and build limits are quoted there. The per-file limit and custom headers were NOT FOUND.
- **The build:** a city build in `C:\Users\studi\Documents\milano-iso\.claude\worktrees\t66data\dist1` (read-only). Measure it yourself:
  - files and bytes, with and without the `.br` and `.gz` copies;
  - the largest file;
  - files per directory.

## Changes
1. **Facts per host.** For GitHub Pages, Cloudflare Pages and Netlify (free tiers), find and quote with URL and retrieval date:
   - the file-count limit and the per-file size limit;
   - the total site size limit;
   - bandwidth or request limits, and fair-use terms;
   - whether precompressed `.br` files are served as-is, and whether the host compresses on the fly with brotli, and for which content types (`.glb` = `model/gltf-binary`, `.json`, `.svg`, JS);
   - whether `_headers` (or an equivalent) is read;
   - the deploy method (Git integration, CLI upload, Actions), and what needs an account.

   Where the docs don't say, write NOT FOUND. Do not guess (hard rule 1).
2. **Fit.** Compare each host's limits with the measured build, and say for each host what we would need to change, for example dropping the `.gz` copies or relying on on-the-fly brotli.
3. **Payload per host.** Using the ADR-0038 figures and each host's documented compression, estimate whether the phone default view stays within 3,000,000 B. Label it an estimate until a deploy measures it.
4. **ADR proposal.** Write the next free ADR number, marked PROPOSED, in `docs/DECISIONS.md`. Recommend one host, with a fallback, and give the reasons. Say exactly what the owner must do: create an account, connect the repository, and any cost (expected none).
