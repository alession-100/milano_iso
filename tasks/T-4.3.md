# T-4.3 - Style v2: land-use, green and water looks, lighting polish, day/night toggle

- **Phase / depends on:** Phase 4 / ADR-0028, ADR-0029. Runs in parallel with T-4.1.
- **Owner:** executor
- **Branch:** t-4.3

## Goal
Finish the flat-layer look (land use and green by kind, water) and add a day/night toggle with a night palette. The owner approves the night look at the Phase 4 checkpoint. The approved day look (palette v1) stays recognisable.

## Inputs
- `CLAUDE.md`; `docs/DECISIONS.md` ADR-0003, ADR-0012, ADR-0025, ADR-0026, ADR-0027, ADR-0028, ADR-0029; `docs/VERIFICATION.md` sections 4 and 5
- `web/src/` (all), `web/e2e/` (all), `web/index.html`, `web/package.json`, `web/playwright.config.ts`
- `pipeline/milano_iso/classify.py` (read only: which `kind` values the landuse, green and water layers carry)
- Real data for local screenshots: `MILANO_ISO_DATA=C:/Users/studi/Documents/milano-iso/data`, `make web-tiles` (never `make data`)

## Changes
1. **Kinds.**
   - Map the land-use, green and water `kind` values to a few colour groups each through a small table, unknown values falling back to the current layer colour. Landuse groups, for example: residential, commercial/retail, industrial/railway, civic/religious, other. Green groups, for example: park/garden, grass, wood/scrub, pitch/playground.
   - Colours go through the existing per-feature lookup (ADR-0026); no extra draw calls.
   - Append new palette entries after the existing ones (ADR-0029, limit 32; set `MAX_PALETTE_COLOURS` to 32 if T-4.1 has not already). Never reorder or recolour palette v1 entries.
2. **Water.** Give water a slightly distinct look within the same material approach, for example a darker edge band or a subtle flat sheen. No animation: rendering stays on demand.
3. **Lighting polish.** Small changes only. Every change to the day look must be listed in the report with before/after screenshots of the same view, because the owner approved the day look.
4. **Day/night.**
   - Add a night palette: a `Record<PaletteName, number>` so that every day entry needs a night colour (typecheck enforces it).
   - Night lights: a cool low "moon" key light and a dim fill. Optional: stylised lit windows on building walls, as a deterministic shader pattern from the feature id. It is flagged as style in code comments and never presented as data.
   - The page background and ground switch with the mode.
   - **Toggle:**
     - a button in the UI with an i18n label (IT/EN) and `aria-pressed`, reachable with Tab and working with Enter and Space;
     - it does not cover the attribution or the tile notice, and is readable at 412 px wide;
     - `?time=night` / `?time=day` set the initial mode;
     - the last choice is remembered in `localStorage`, every access wrapped in try/catch;
     - the default is day.
   - Switching renders one frame on demand; no permanent render loop.
   - Expose the mode via `registerTestState('style', ...)`.
5. **Tests.**
   - Unit tests:
     - the kind mapping, including unknown values falling back;
     - the night palette covers every entry;
     - the palette has <= 32 entries.
   - e2e:
     - the toggle switches the mode by mouse and by keyboard;
     - `?time=night` starts in night mode;
     - zero console errors (ADR-0012 filter only).
   - Visual: add night candidate baselines (default and close views, both viewport sizes) to `visual.spec.ts`. Regenerate the win32 baselines that change, deleting the old ones first (see the snapshots README). Leave `*-linux.png` untouched: the orchestrator handles them.
