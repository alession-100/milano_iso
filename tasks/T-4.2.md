# T-4.2 - Landmark models: DBT massing plus flagged stylised details

- **Phase / depends on:** Phase 4 / ADR-0016, ADR-0020, ADR-0028, ADR-0029. Starts after T-4.1 and T-4.3 are merged, because it changes the exporter, the fixture and the palette.
- **Owner:** executor
- **Branch:** t-4.2

## Goal
Make the landmarks recognisable. Their real DBT massing stays exactly as it is, and a few stylised details are added on top: for example the Duomo's spires and pinnacles, Torre Velasca's roof crown, and the Galleria's glass roof (deferred from ADR-0016).
- **In-pilot landmarks** (`in_pilot: true` in `tests/landmarks.yaml`, group `phase4`, plus the Galleria) are placed in the pilot tiles now.
- **Out-of-pilot landmarks** (group `phase4`, `in_pilot: false`) get their detail specs built and unit-tested now, but are placed and verified in Phase 6 (ADR-0028 decision 2).

## Changes
1. **Detail specs (style).**
   - Write one small, declarative spec per landmark in a style module, for example `pipeline/milano_iso/landmark_style.py`.
   - A spec lists low-poly primitives (spire, pinnacle row, crown, vault) and where to put them **relative to the landmark's own rendered DBT volumes**: on the top of a named volume, along a footprint edge, at the footprint centroid, and so on.
   - Every size, count and spacing is a named style constant, documented as style.
   - Do not invent "real" figures. If you want a detail at a real height (for example the Duomo's main spire), take it from the DBT volumes, or from a source cited in the report with URL and retrieval date. Otherwise it is a style constant and is labelled as such.
2. **Galleria glass roof.**
   - Model a stylised vault over the OSM `building=roof` footprint that ADR-0016 does not render.
   - Its base height comes from the data: for example the eave height of the adjacent Galleria DBT volumes. State the rule, and the numbers it gives, in the report.
3. **Export.**
   - Add a layer `landmark_details` to the tiles. Each row has `landmark_id`, `detail` (the primitive kind) and `stylised: true`.
   - The `buildings` layer must be unchanged: its meshes and feature table are byte-identical to the build before this task. Prove it with a hash comparison per tile.
   - Byte-identical rebuilds still hold; each tile stays <= 250 KB gzip.
   - Update the schema and the manifest layer list.
4. **Placement checks** (`tests/data`):
   - Every detail of a landmark lies within that landmark's rendered footprint union, buffered by a style-constant tolerance of at most 2 m.
   - No detail's base is below the top of the volume it sits on.
   - The existing landmark checks (ADR-0017/0018/0020: centroid within 5 m, best-fit offset <= 5 m) still pass unchanged.
5. **Client.** Render `landmark_details` with the existing per-layer material approach (one material, no extra draw calls beyond one per tile that has details). Give it a colour derived from the landmark accent (append palette entries if needed, ADR-0029). In night mode (T-4.3), the night palette must cover the new entries.
6. **Out-of-pilot landmarks.**
   - Write specs for San Siro, the CityLife towers, Bosco Verticale, Pirelli, Stazione Centrale and the Castello Sforzesco, and unit-test them on synthetic volumes.
   - If the pipeline can already process a small AOI around one of them from the raw data (without changing pilot outputs or config defaults), add preview screenshots. If it can't, say so in the report and leave the previews to Phase 6.
7. **Fixture.** Give the fixture's landmark building a small detail spec, so the visual regression covers the layer. Regenerate the fixture through the real exporter, and regenerate the changed win32 baselines (delete them first). Leave `*-linux.png` untouched.

## Constraints
- No new dependencies. Never change a footprint, a height from data, the origin, or `tests/landmarks.yaml`.
- Every stylised element is flagged in the data (`stylised: true`) and in code comments.
- Commit messages end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Acceptance criteria
1. `make test`, `make validate` (with `MILANO_ISO_DATA=data_t42`) and `make check-determinism` exit 0, including the new placement checks. The buildings-layer hash comparison shows 0 changed tiles.
2. The web typecheck, lint, unit tests and build pass; the full e2e passes 3 consecutive times.
3. Real-data report:
   - draw calls at the default view and at 4000 m (<= 300);
   - max tile gzip size;
   - screenshots at 1280x720 and 412x915 of a 150 m view of the Duomo, of Torre Velasca and of the Galleria, by day and by night, saved to `reports/artifacts/T-4.2/`;
   - a table of every detail constant and its status (style, or sourced with URL).
4. `git status --short` empty; no server left on 4185; committed on `t-4.2`; `reports/R-4.2.md` written.

## Escalate if
- A detail cannot be placed without changing data-derived geometry.
- The Galleria roof footprint or its adjacent volumes cannot be identified unambiguously.
- A tile exceeds 250 KB gzip, or the default view exceeds 300 draw calls.
