# T-1.3 - Normalise OSM and DBT into validated layers in EPSG:32632

- **Phase / depends on:** Phase 1 / T-1.1 and T-1.2 (merged). Runs in parallel with T-1.5 (no shared files).

## Goal
Turn the two raw pilot extracts into clean, classified, valid layers in EPSG:32632. Log every dropped or repaired feature with a reason, and write a validation report. Heights and the merging of OSM with DBT are not part of this task (T-1.4).

## Rules
- **Reprojection.** Use pyproj with `always_xy=True`: EPSG:4326 to 32632 and EPSG:7791 to 32632. In `transform.md`, record the operation each uses and its stated accuracy. Keep Z values on DBT volumes for the `base_z_*` columns, but store 2D geometries.
- **Validity.** Repair invalid geometries with `shapely.make_valid`, keeping polygonal parts only. Record each repair (id, layer, the reason from `shapely.is_valid_reason`) in the drop log with action `repaired`. Drop zero-area polygons and zero-length lines (action `dropped`, reason). Remove exact duplicates (same geometry and same key) and log them.
- **No simplification here.** The tolerance of <= 0.5 m from VERIFICATION applies only at tile export.
- **Underground.** Keep features with `tunnel=yes`, `location=underground` or a negative `layer`, but flag them `underground=true`. Underground DBT volumes are kept and flagged if the spec codes identify them; otherwise leave as is and note it.
- **Classification.** Every OSM object is assigned to zero or more layers by `classify.py`. Write the counts of objects assigned to no layer to `validation.json`, by top tag key. Do not invent categories beyond the table; put unknowns in `landuse` only if they carry `landuse=*`.
- **Determinism.** Rows are sorted by key, and the run is repeatable: the canonical-dump sha256 must be identical across two runs. Reuse or move the existing canonical-dump function so both modules share it.
- **Drop log columns:** `layer, source, id, action, reason`. Sort it.

## Validation report (`validation.md` / `.json`)
- **Per layer:** input count, output count, repaired, dropped (by reason), duplicates.
- **Completeness:**
  - DBT volumes out / in (target >= 99%).
  - OSM buildings out / in, where "in" is the number of `building=*` areas in `osm_pilot.gpkg` (target >= 99%).
- **CRS assertion:** every layer is EPSG:32632.
- **Validity assertion:** every geometry is valid.
- **Extent assertion:** every feature intersects the pilot extent.

## Acceptance criteria
1. `make data` runs every step end to end. A second run downloads nothing and gives the same canonical sha256 for `processed/pilot.gpkg`; show both.
2. `validation.json` shows: CRS EPSG:32632 for every layer, 0 invalid geometries, 100% of features intersecting the extent, completeness >= 99% for both DBT volumes and OSM buildings. If a figure is below 99%, report it as a failure; do not change the denominator.
3. The `dbt_volumes` with a non-null `building_class` count at least the 4,610 already matched to `EDIFC_CR_EDF_ME`, plus those matched to `EDI_MIN`. Report the final unmatched count, which is expected to be 0.
4. `drop_log.csv` exists; every row has a reason.
5. `make data-dbt` still logs a skip after the `fetch.py` refactor.
6. Unit tests cover:
   - classification rules: at least one case per layer, including a closed roundabout way and a pedestrian `area=yes` square;
   - make-valid repair logging;
   - duplicate removal;
   - underground flagging;
   - deterministic ordering.
7. `make test` exits 0. `git status --short` is empty; committed on `t-1.3`.
