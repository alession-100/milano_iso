## Deviations and assumptions
- **Console warning filter (e2e):** headless Chromium with SwiftShader emits `GL Driver Message ... GPU stall due to ReadPixels` as a console warning whenever a WebGL canvas is screenshotted. The test ignores exactly that message (regex) and fails on any other error/warning/pageerror. The app itself produced no warnings. Orchestrator may judge whether this meets "zero console warnings".
- Playwright launches Chromium with `--use-angle=swiftshader --enable-unsafe-swiftshader` so WebGL works headless on CI and this machine.
- typescript resolved to 6.0.3 (npm "latest" for the peer range of typescript-eslint), although `npm view` listed 7.0.2 as newest.
- Added `pyyaml` (dev) for the YAML check, `@eslint/js` and `@types/node` as npm dev deps (needed by ESLint config and `process`/`node:` in e2e). Added hatchling as build backend.
- `playwright.config.ts` webServer runs `npm run preview` (port 4173); e2e requires `npm run build` first (as in the CI order and the card's commands).
- Screenshot output path is resolved from `process.cwd()` (`web/`), so e2e must be run from `web/` (as `npm --prefix web` does).
- CI installs Chromium with `--with-deps`; CI itself was not run (no remote).
- Scene sizes/colours/camera view height (24 m) are my own arbitrary hello-world choices.
- Comparison for the owner: 35.264 deg shows a steeper view than 30 deg (2:1 rhombi).
