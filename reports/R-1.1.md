## Deviations and assumptions
- The card's verification query reads the relative path `data/interim/osm_pilot.gpkg`; with the shared `MILANO_ISO_DATA` cache the file lives elsewhere, so I used `os.environ['MILANO_ISO_DATA'] + '/interim/osm_pilot.gpkg'`.
- The first download of the two sources ran via `python -m milano_iso.fetch` (what the make targets invoke) before the make run, so the logged `make` run shows "skip". Manifests were written by that first run.
- The `.md5` file is also saved to `data/raw/osm_geofabrik/`.
- Failed area assembly: pyosmium emits an empty area (0 rings) for relations it cannot assemble; I count those plus multipolygon/boundary relations that produced no area at all. The extent is NOT applied to these (cannot, there is no geometry), so the 509 IDs are the whole NW-Italy file, not just the pilot AOI. Most are probably relations with members outside the Geofabrik clip; I did not investigate individual IDs.
- Closed ways that osmium treats as areas (it creates an area for any tagged closed way unless `area=no`) go to `areas` only; the same way is not also emitted as a line. This includes closed highways such as roundabouts: they appear as polygons in `areas`, not in `lines`. T-1.3 classification needs to know this.
- Extent edge uses `intersects` (touching counts). Densified extent has 12 vertices per edge (spec: at least 10).
- Node/way lines with invalid locations would be listed under `failed_geometry` (none occurred).
- `osmium` pulled in `requests` and friends as transitive dependencies (not directly used by our code).

## Open questions and risks
- 509 failed relations in the full file: whether any intersect the pilot AOI is unknown. If the Duomo-area relations matter, T-1.3 or a follow-up should check specific failures (e.g. by comparing against Overpass).
- `city` extent is implemented but untested on real data; at city scale the Python callbacks are the same cost (full file read), but output size is larger.
