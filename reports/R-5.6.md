## Deviations and assumptions
- **Footways, steps and non-platform `footway=sidewalk` ways stay streets** (ADR-0033). In the pilot they are real named passages (Galleria Pattari, Galleria Unione, Passaggio Duomo, Via Speronari, Via Brolo, Galleria del Toro); dropping them would remove real streets (an escalation condition). Consequence: "Nuovo accesso M3" (footway + steps, no platform tag) remains a street, since a tag-only rule cannot tell it apart. The card named it among the platform-pattern entries; it is not tagged as a platform in the data.
- **The platform flag needed a change in `normalise.py`** (new `roads.is_platform` column). The tags exist in `interim/osm_pilot.gpkg`; the OSM extract step is unchanged, so the escalation condition did not apply. `processed/pilot.gpkg` therefore has one more column; `make data` must be re-run on a real data checkout (as done here) before `make tiles` shows stops. The canonical gpkg sha256 changes (tooling `check-determinism` re-baselines were not run by me).
- `INDEX_FORMAT_VERSION` kept at 1 (older clients drop unknown kinds; reasoning in ADR-0033).
- Tie-break beyond the card: for equal folded names a street is listed before a stop (otherwise "Largo Augusto | Fermata" came first alphabetically). Rest of the "existing order" unchanged.
- Landmarks-first also applies inside the exact-match group; an exact match of a non-landmark (a building literally named "Duomo", if it existed) still comes first, as the card says.
- I edited `tests/data/test_data_index.py` (the KINDS list); it is a data-validation test, not part of `make test`.
- The mobile toolbar win32 baseline was regenerated (ranking). If T-5.5 also regenerates the toolbar baselines, expect a merge conflict on the PNG: take T-5.5's layout and re-run the update. No Linux baseline exists for the toolbar tests.
- `toolbar.ts` is touched in one line (`KIND_KEY`), which T-5.5 may also edit; trivial to merge.

## Open questions and risks
- Windows only: Linux CI for `index.json` byte identity is unverified here (no Linux run). The new code uses only grouping and sorting, no geometry operations beyond what the index already did.
- "Nuovo accesso M3" and similar non-tagged station accesses remain "Via"; the owner may want a tag-based rule later (for example an `entrance`/`railway=subway_entrance` link) if the OSM tags allow it.
