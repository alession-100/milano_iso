## Deviations and assumptions
- The card's table is "one row per host, one column per fact"; with 10 facts and long cells I wrote one table per host with one row per fact. Same content.
- dist1 has **no** `.br`/`.gz` copies, so the "with copies" figures are an upper bound and an estimate from ADR-0038, not a measurement. dist2 and `t66data/tiles` have none either.
- Fetches were made through the WebFetch tool, which summarises a page with a small model; quotes are the tool's verbatim extracts. The Cloudflare build timeout (20 minutes) and the Netlify CLI `--prod` quote came from search-result excerpts of the official pages, not a full fetch.
- The Netlify brotli fact is from Netlify's own blog (2020), not the docs; its docs pages read (headers, troubleshooting, credits, pricing) do not mention compression.
- The Netlify legacy-plan usage URL returned 404; the current credit-based pages were used.
- Forum threads (answers.netlify.com) and third-party posts appeared in searches (for example, statements that Netlify does not serve precompressed files and that GitHub Pages gzips); they are not used as facts.
- "`.glb` likely served raw on Cloudflare" is an inference from the absence of `model/gltf-binary` from the documented list, not a documented statement.

## Open questions and risks
- **Main risk:** the 3 MB phone budget needs the tiles compressed on the wire; no host's docs confirm it for `.glb`. Possible remedies, not researched here and each needing a decision: a probe deploy on the recommended host; a custom domain with a Compression Rule (cost, ADR-0008); a client-side decode of `.br` tiles (bundle size and browser support not checked).
- Cloudflare Direct Upload cannot later switch to Git integration; deploys come from the owner's machine or an Actions job that has the tiles (they are not in Git).
- Netlify's hard cap pauses all of the owner's Netlify sites when 300 credits are used.
- GitHub Pages: per-file limit, headers and compression remain NOT FOUND (as in R-0.3).
