- `web/src/style/trees.ts`, `web/src/tiles/loader.ts`: instance-to-row mapping on the tree mesh, feature table kept on the tile group.
- `web/src/main.ts` (delimited `// --- T-5.1 picking ---` block plus three one-line hooks), `web/src/i18n.ts` (card strings).
- Tests: `web/src/pick/pick.test.ts` (15 unit tests), `web/e2e/picking.spec.ts` (15 e2e tests), 2 new visual baselines (win32 only) in `web/e2e/visual.spec.ts`.
- `web/scripts/measure-pick-real.mjs`: real-data evidence script. Evidence in `reports/artifacts/T-5.1/`.
- Not touched: `selection.ts`, `pipeline/`, fixture, toolbar/search/minimap code. `visual-hide-controls.css` needed no change (the card must be visible in its own baseline).

## Deviations and assumptions
1. **No existing click threshold.** `controls.ts` has none, so `CLICK_SLOP_PX = 6` (and "a second finger is a pinch") is defined in `pick/picker.ts` as a style/UX constant. `controls.ts` is unchanged.
2. **`index.json` is fetched on the first selection**, not at start, so that T-5.3b's "not fetched until the search box is used" test still holds. Names of streets, parks and landmarks therefore appear a moment after the card opens on the very first pick (tests poll the title).
3. **Rail and road areas are not pickable.** The card lists roads, green, water and land use only; markings and fill trees never pick.
4. **A mapped tree row shares one OSM id** (a `tree_row` way), and the ref (`FeatureRef`, unchanged) has no instance index, so selecting one tree of a row highlights all its trees; the card shows the height of the first row.
5. **Landmark cards show no height.** The ref identifies a landmark, not a building, and a landmark may be several volumes; only name, type and the stylisation note are shown.
6. **Highlight tint** is a style constant (warm yellow, mixed 42 % for hover, 62 % for selection; trees use an instance colour multiplier). It is not a palette entry.
7. **Language switching** has no UI in this task: the card follows `DEFAULT_LANG` and has `setLang()`; no toggle was added.
8. **`?debug` layout:** the card moves left of `#debug-overlay` when it is present (both sit at right, top 104 px).
9. The new visual baselines are win32 only; the tests are skipped on other platforms (no Linux baseline exists, as for T-5.3b). Existing baselines were all unchanged.
10. Height values are rounded to one decimal for display (`30,473` shown as `30,5 m`).
11. The real-data screenshot script was run once on the merged build; the first pre-merge screenshots were overwritten.
12. The card for a DBT building has no OSM link (the data holds no OSM id for DBT-only keys); OSM-keyed buildings link to the way/relation.

## Open questions and risks
- **Hover pick time:** within the 4 ms limit on the final real-data run (mean 0.97 ms, worst move 6.3 ms on desktop; indicative). The pre-merge run was worse (see above). If the Phase 6 whole-city data makes it slower, add a spatial index per tile.
- Focus after a pick moves into the card, so keyboard map navigation resumes after Escape (focus returns to the map) or a click on the map.
- Contrast and screen-reader checks of VERIFICATION 4a are not claimed here; the reviewer should check them, including the card at night.
