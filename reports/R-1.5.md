## Deviations and assumptions
- Extra top-level key `landmarks:` (list under it) and extra per-entry key `group` (phase4 | pilot_ref); not in the card's field list, used by the test.
- Added `fetch_landmarks.py` (not listed in outputs) so that the saved responses are reproducible; the build script is offline as required.
- Retrieval date `2026-11-15` is a constant in the build script (the date of the fetches; Overpass base timestamps in the responses are 2026-11-15T20:15Z-20:28Z). OSM element versions/timestamps come from the saved API responses.
- The QID-to-landmark choice and OSM element choice are hard-coded in `SELECTION`, with checks against the saved search and Overpass responses.
- Wikidata search for the CityLife towers returned labels by architect (Torre Isozaki/Hadid/Libeskind); Q651643 "Torre PwC" (description only "skyscraper") was not examined; see choices.md.
- The Bosco Verticale towers share one QID (Q2501413); each is its own entry, with its own OSM way. Tower names are the OSM names.
- Overpass was loaded: several requests were retried after 504/502 with 10 s back-off; no block was circumvented.
- `PYTHONUTF8` not needed in the script (utf-8 explicit). Ran with `MILANO_ISO_DATA` set though no data dir is used by this task.

The entry uses the node (`method: node`), 32.5 m from P625, not the station building footprint.
