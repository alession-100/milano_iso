`Content-Type: model/gltf-binary` for .glb. An `Accept-Encoding: br`-only request to a level-1 .glb also has no `Content-Encoding`. The .glb sizes on the wire equal the manifest's raw `bytes`; the manifest's gzip-9 sizes are 59,990 (level 0), 134,011 (level 1) and 138,849 (level 3) B. JSON, SVG and JS are compressed by the edge (zstd or gzip, never br).
- **`_headers`:** took effect for `/assets/*` and `/tiles/*` (immutable) and `/`, `/index.html` (no-cache). Problem: `tiles.json` matches both rules and the host **adds** them: `immutable, no-cache` (the browser must revalidate because of no-cache, and the client also uses `cache: no-cache`, so the effect is probably nil, but it is not the intended value). `/index.html` answers 307 to `/`. Whether static requests went to the Worker or straight to assets: not determined (no Worker code exists; there is no header that says it).
- **Payload runs (412x915 and 1280x720, 3 runs each): NOT RUN.** The card says to stop when .glb tiles arrive uncompressed. Estimate only, not a measurement: ADR-0038 measured the phone default view as 4.44 to 4.63 MB with a gzip-only client, and these glb files are not even gzip-compressed on this host, so the phone view is expected to be well above 3,000,000 B (the glb part alone would be larger than the 2.48 to 2.57 MB with brotli).
