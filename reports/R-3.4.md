## Design
- Off by default: `debug.ts` is a separate chunk loaded only with `?debug`. Without it, `frameHooks` is an empty array.
- Benchmark: a frame hook runs after every `render()`. While the benchmark runs, the hook sets the camera from `benchPose(elapsed)` and calls `requestRender()`, giving continuous rendering without changing the on-demand model. When it ends, the hook stops requesting frames.
- Path (fixed keyframes, seconds, x, z, width): (0, -400, -400, 600), (5, 400, 400, 4000), (10, -400, -400, 600). Linear in position, geometric in width, time-based. The rig clamps the target to the manifest bounds.
- Results: `meanFps = 1000 / meanFrameMs`; `p5Fps` = 5th percentile (linear interpolation) of per-frame fps; `p95FrameMs` = 95th percentile of frame time. Frame time is the interval between consecutive rendered frames; the first frame only sets the time origin.
- Overlay: fixed top-left, max width min(380px, 100vw-12px), 11px monospace, so it is readable at 412 px and away from the bottom-right attribution; close button; buttons are native `<button>` (Tab, Enter).

## Deviations and assumptions
- `main.ts` has two one-line edits outside the delimited block: `const frameHooks` declaration and the `for (const hook of frameHooks) hook();` call at the end of `render()`. Needed so the overlay updates after each rendered frame and can drive continuous rendering; no other change to the render model.
- Headed Chromium: `chromium.launch({headless:false})` failed with `spawn UNKNOWN` in this environment, so only the headless result exists.
- The 412-px layout is by CSS (max-width, wrapping); I did not add a dedicated 412-px e2e or screenshot. The e2e only checks the overlay does not overlap the attribution at 1280x720.
- Bench keyframes (-400..400 m, 600..4000 m) are my choice from the card's description ("pan across pilot area, zoom 600 to 4000 m and back"); the pan range is not derived from the manifest bounds.
- `i18n.ts` was edited (card lists it as an input and the spec requires an i18n label).
- `web/public/tiles/pilot` (gitignored) was populated by `make web-tiles` for the real-data run.

## Open questions and risks
- A `vite preview` server I started for the real-data run is still listening on port 4173 (PID 40380); my attempt to stop it was denied by the permission system. It will collide with `npm run e2e` (`--strictPort`, `reuseExistingServer: false`) for T-3.3 or the orchestrator until it is stopped manually (e.g. `taskkill /PID 40380 /F`).
- Frame-time statistics include time spent in `requestAnimationFrame` throttling; on a 60 Hz display fps is capped near 60.
