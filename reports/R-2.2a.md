# R-2.2a - Compact tile encoding (corrective for T-2.2, retry 1/2)

- **Status:** BLOCKED (ADR-0022 point 2 cannot be met for 7 rendered buildings; `make tiles` fails loudly, as the card requires for out-of-range values)
- **Branch / commits:** `t-2.2a` (one WIP commit with the implementation; no tile run completed, no gate evidence)

## What changed
- `pipeline/milano_iso/tiles/geom.py`: `MeshBuilder` now builds indexed meshes with shared vertices (key = x, y, z, feature id); no normals; winding unchanged (counter-clockwise from outside). `to_gl_chunks()` returns float64 client-frame chunks of at most 65,535 vertices (triangles kept whole, insertion order).
- `pipeline/milano_iso/tiles/glb.py`: int16 `POSITION` (cm from the tile centre, y = 0), `KHR_mesh_quantization` in `extensionsUsed` and `extensionsRequired`, node translation = tile centre (client m) and scale 0.01, accessor min/max in quantised units, out-of-range raises `ValueError`, uint16/uint32 index and `_FEATURE_ID` selection at 65,536. `NORMAL` removed.
- `pipeline/milano_iso/tiles/export.py`: all tiles holding a rendered building's representative point are exported (the `--include-outside` flag is gone; behaviour is now always on); flat layers clipped to the pilot extent and the tile; chunk meshes named `<layer>#<n>` only when split; stale `*.glb`/`*.json` removed from the output dir before export; per-tile `position_sample` (128 vertices, float64 client metres), `gzip9_baseline_t22` (before column), centre, mesh names written to `export_summary.json`; markdown table has the before/after column.
- `web/scripts/load-tiles.mjs`: sums chunks per layer, asserts `KHR_mesh_quantization` in used and required, dequantises through the node matrix and compares with the sample (tolerance 0.01 m, sample must be >= 100), reports the counts.
- `tests/pipeline/test_glb.py`, `tests/pipeline/test_tiles_geom.py`: updated and extended (see criterion 5).

## Deviations and assumptions
- Blocked rather than changing the quantisation scheme: ADR-0022 point 2 fixes the offset origin to the tile centre; widening or re-anchoring it is an ADR change, not mine to make.
- Assumed: the first 5-point spec "offset from the tile centre" also applies to buildings from other tiles (they cross tile edges, as the Duomo does).
- glTF alignment: int16 VEC3 `POSITION` uses `byteStride` 8 (2 padding bytes per vertex, which gzip removes); `_FEATURE_ID` and indices are tightly packed with no stride (so a uint16 scalar element is 2 bytes, not 4-aligned per element; every accessor/view offset is 4-aligned). A glTF validator was not available to confirm this reading.
- Unsplit meshes keep the name `<layer>`; `#<n>` is used only when a layer is split. Nothing needed splitting before the failure, so this is untested on real data.
- Chunk split is greedy between triangles, so a building can straddle two chunks; feature ids are per vertex, so this is harmless to picking.
- Brotli remains optional and absent (no new dependencies).
- The python edit helper wrote CRLF and a stray NUL at first; fixed to LF and `b"\0"` before the commit.

## Open questions and risks
Decision needed from the orchestrator (ADR-0022 point 2 amendment). Options, none implemented:
1. Anchor quantisation per mesh (or per chunk) at the centre of its own bounding box (rounded to a whole metre, written into that node's translation). Always in range if a chunk's extent is under 655 m; the largest tile content here (tile extent 500 m plus the 31 m overshoot beyond the limit on each side) should fit, but must be measured.
2. Use uint16 (non-normalised, offset from tile SW corner minus a 100 m margin): range 0 to 655.35 m. Simple, but needs the margin to cover 109 m worst case on both sides (500 + 2 x 109 = 718 m), which does not fit; not recommended.
3. Cut the buildings at the tile edges. Rejected: it breaks "each building in exactly one tile".
Option 1 is the closest to ADR-0022 intent. With the card's retry limit (1/2 used by T-2.2a), please amend the ADR before the next card.
