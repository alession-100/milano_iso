## Deviations and assumptions
- **BLOCKED on three gaps** the card forbids me to fix (heights rules, style tables, data defects go in the report). Each needs a decision:
  - **A. One building cannot be grounded.** `heights.dbt_volume_heights` fails loudly (ADR "no POR 01 volume: median of >= 5 POR 01 volumes within 50/100 m"): `EDIFC_2797`, one `POR 04` volume, 238.0 m2, centroid E 516499.8 N 5037711.5, 0 POR 01 volumes within 100 m. 187 buildings need the neighbour rule; this is the only one that fails it. Options: wider radius, own `base_z_min` as ground (flagged), or do not render it.
  - **B. 287 render volumes (197 buildings) have height 0** (`UN_VOL_AV` = 0, e.g. `UN_VOL_1017` of `EDIFC_16076`, `UN_VOL_1023`..`1037` of `EDIFC_20611`); `check_layers` ("height_m > 0") then fails and `heights` exits 1. The pilot had none. Options: drop with a logged reason, or take the default height. Not done (heights rule).
  - **C. Style widths are missing for classes the pilot does not have** (decor and export raise `KeyError: no style width for class 'primary'`): roads `motorway` 669, `trunk` 447, `primary` 1,988, `secondary` 2,802, `living_street` 24, `track` 562, `other` 276; rail `rail` 2,486 (`RAIL_WIDTH_M` has only subway and tram). These are style constants (`style.py`); the numbers are a design choice, so I did not invent them. The experiment used placeholders (12, 10, 9, 8, 5, 3, 3 m and 3 m), which are NOT proposed values.
- The check "every feature intersects the extent" accepts 1e-6 m. Without it 38 `named_features` points (lines clipped to the comune, then `point_on_surface`) failed by about 1e-10 m and `normalise` exited 1. Same semantics for the pilot (0 outside before and after).
- `make validate EXTENT=city` is not implemented: `tests/data` assume the pilot (`in_pilot` landmarks, the AOI box, the pilot paths). They now refuse to run for another extent instead of silently validating the pilot.
- ADR number: 0035, not 0034 (already used by T-5.7). The ADR is Proposed.
- The city JSON key for the GeoPackage hash is `canonical_dump_sha256_city_gpkg`; the pilot keeps the old key.
- `make -o data-boundary -o data-osm -o data-dbt data-normalise ...` was used to rerun later steps without redoing the 5 min of extraction; `make data` itself is not incremental and I did not change that.
- The wrapper records the largest single process of the tree (a venv `python.exe` is a launcher; the real interpreter is its child), not a sum. Steps run one at a time, so this is the step peak.
- Experimental stop-gaps (A, C) lived only in scratch scripts outside the repository. `data/processed/city.gpkg` in my data dir is therefore an experimental file (heights and decor layers built with the stop-gap); it must be rebuilt after the decisions.
